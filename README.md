# X-WRT firmware build definitions

This branch builds a customized Tenda BE12 Pro image from an exact official
[`x-wrt/x-wrt`](https://github.com/x-wrt/x-wrt) release tag. It does not require
long-lived source or feed forks.

## Customization model

All device-specific policy lives in [`profiles/tenda-be12-pro`](profiles/tenda-be12-pro):

- a minimal, reviewable `config.seed` generated by X-WRT's `diffconfig.sh`;
- required and excluded package lists checked after `make defconfig`;
- immutable custom-package commits and build-time geodata hashes;
- patches applied with `git apply --check` before the build;
- scripts that configure the source and write a provenance manifest.

The profile selects only the Tenda BE12 Pro, uses Sing-box and MosDNS, and
excludes OpenClash and HomeProxy. Official feeds come from the selected source
tag's `feeds.conf.default` and are not redirected to a custom feed branch.
Sing-box itself is resolved at build time through GitHub's official
`releases/latest` API. Drafts and prereleases are rejected, and the API release
metadata plus resolved source hash are included in `build-manifest.txt`.

## GitHub Actions

Run **Actions → x-wrt-tenda-be12-pro → Run workflow**. Leave `release_tag`
empty to use the newest official tag, or enter a tag such as
`26.04_b202609050853`.

The hourly scheduled run performs the same lookup. It rebuilds when either the
official X-WRT tag changes or a newer stable Sing-box release appears; otherwise
it skips the existing release. A manual run always rebuilds the selected tag.
Successful runs publish:

- the initramfs and sysupgrade `.bin` images directly;
- `sha256sums.txt` covering both images;
- `build-manifest.txt`, containing exact source, feed, and custom-package
  revisions plus data hashes.

The tracked `release.tag` file is retained for historical compatibility only;
the workflow neither reads nor updates it. This avoids CI commits and races
between scheduled builds.

From a clone of this repository, the following helper dispatches a manual run
for a specified tag. With no argument, it selects the newest official tag:

```sh
sh update-tags.sh 26.04_b202609050853
```

## Local preparation and build

The preparation host needs `git`, `curl`, and `jq`. An authenticated `gh` CLI
is used for the API request when `GH_TOKEN` is available; otherwise the public
GitHub API is called directly.

Use the same ordering as CI:

```sh
tag=26.04_b202609050853
git clone --depth 1 --branch "$tag" https://github.com/x-wrt/x-wrt.git x-wrt
(cd x-wrt && ./scripts/feeds update -a && ./scripts/feeds install -a)
sh prepare-custom-packages.sh x-wrt
sh profiles/tenda-be12-pro/configure.sh x-wrt "$tag"
cp x-wrt/.config x-wrt/feeds/x/rom/lede/config.nico-tenda-be12-pro
cp build.sh upload.sh x-wrt/
(cd x-wrt && env \
  PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  CONFIG_VERSION_NUMBER="$tag" bash build.sh "$(nproc)")
```

`configure.sh` rejects a stale seed rather than silently changing package
selection when a new upstream tag changes Kconfig. Regenerate and review the
seed against that tag before accepting such an update.
